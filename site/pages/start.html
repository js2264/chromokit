Get started

chromokit is copied into a project, not installed in it: one command writes a starter site and the kit's files, and records which files are the kit's so they can be updated later. Nothing needs to be published anywhere first — the command runs straight from GitHub.

Start a site

npx github:js2264/chromokit init <target> [dir] --name hicool --description "Hi-C maps in one command." --repo js2264/hicool

It writes two kinds of file:

  • Starter files — the config, a home page, a stylesheet of your own — with the project's name filled in. They are yours from then on: chromokit never touches them again.
  • Kit files — stylesheets, templates, scripts — listed with their hashes in chromokit.json. Keep them as they are: chromokit sync replaces them with a newer version, and chromokit check fails if one was edited. A local change belongs in your own stylesheet, which loads after the kit's.

It also draws the project a logo mark from its name, and with --accent "#7a3e9d,#b98ad6" gives it its own accent colour (light, then dark) over chromokit's blue. --dry-run shows what would be written.

Plain HTML

npx github:js2264/chromokit init html

A landing page and a documentation page with a sidebar and "On this page", and the kit in assets/chromokit/: chromokit.css (tokens, components and the page layout), theme.js (in <head>, so a dark-mode reader never sees a white flash) and chromokit.js (copy buttons, arrow keys, the contents highlight).

Hugo

npx github:js2264/chromokit init hugo
hugo server

A theme in themes/chromokit/ — layouts, a code-block hook, Chroma's colours from the tokens — with shortcodes for the landing page: tiles, tile, actions, callout, badge, kicker. Your own layouts/ override any of the theme's. With a menu.main in the config, the sidebar and the previous/next links follow it, so a personal site of a few pages needs no sections; params.links adds icon links to the header, params.header = false leaves the header out and puts the name, the links and the theme toggle in the sidebar, params.palette = 'light' keeps one palette and drops the toggle, params.showDescription = false keeps descriptions out of the page, a shortcode that draws its own sections can give "On this page" its list (.Page.Store.Set "chromokit.toc"), and layouts/partials/chromokit/extend-head.html adds to <head>.

Zensical

npx github:js2264/chromokit init zensical
uv run zensical serve

For a Python package's documentation, as metacooler's: a zensical.toml, the header and in-column footer in overrides/, the stylesheet and the arrow keys in docs/. The release beside the name is extra.release; an optional header button is extra.cta. It works the same with Material for MkDocs.

Sphinx

npx github:js2264/chromokit init sphinx
pip install -r docs/requirements.txt && sphinx-build docs docs/_build/html

For a Python package already on Sphinx: the Furo theme, restyled by docs/_static/chromokit.css, with the sidebar's brand (mark, name, kicker, release) in docs/_templates/sidebar/brand.html, and MyST Markdown pages. The kicker is html_context["chromokit_kicker"] in conf.py.

Astro Starlight

npx github:js2264/chromokit init starlight
npm install && npm run dev

doc.chromosomix.app's look, over the Rapide theme: a Starlight plugin in src/chromokit/ that adds the stylesheet and swaps in the header and footer, and Masthead, Tiles, Tile and Callout components for MDX pages. From npm, the plugin is import chromokit from 'chromokit/starlight'.

pkgdown

Two ways. As a template package, which pkgdown is built for — in _pkgdown.yml:

_pkgdown.yml
template:
  package: chromokit

and Config/Needs/website: js2264/chromokit/r in DESCRIPTION, so the site's CI installs it (pak::pak("js2264/chromokit/r") locally). The R package's own site, built that way, is at r/. Or by copy, with no dependency:

npx github:js2264/chromokit init pkgdown
Rscript -e 'pkgdown::build_site()'

which writes pkgdown/extra.scss (the kit, compiled by pkgdown into Bootstrap), the settings in _pkgdown.yml, your own pkgdown/extra.css, the logo and the favicon.

Quarto

quarto add js2264/chromokit

adds the extension to any Quarto project; then format: chromokit-html for documents, websites and books, or format: chromokit-revealjs for slides. For a whole starter website: npx github:js2264/chromokit init quarto. dist/brand/_brand.yml carries the palette as brand.yml, for Quarto, Shiny and bslib.

Keeping up to date

npx github:js2264/chromokit@v0.2.0 sync    # the kit's files, at that version
npx github:js2264/chromokit check          # in CI: fails if a kit file was edited

sync refuses to overwrite a kit file you edited (--force does); a file the kit no longer ships is removed.

Other ways in

  • A link, for any page: https://cdn.jsdelivr.net/gh/js2264/chromokit@v{{version}}/dist/css/chromokit.css (tokens and components) or …/chromokit-page.css (with the page layout).
  • npm: npm install chromokit, then import 'chromokit/tokens.css' in an app, or the tokens as data from chromokit/tokens.
  • Only the tokens: dist/css/tokens.css (custom properties), dist/scss/_tokens.scss (Sass), dist/tokens/tokens.json.

Plots

Figures in the same colours: dist/plots/chromokit-light.mplstyle for matplotlib (plt.style.use(url) takes the jsDelivr link), ECharts and Plotly themes as JSON, and in R theme_chromokit() with scale_colour_chromokit() from the R package.
